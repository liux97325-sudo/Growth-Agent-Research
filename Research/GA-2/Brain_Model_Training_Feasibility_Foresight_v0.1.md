### 0.1 本报告回答什么

| 问题 | 回答位置 |

| 资源与时间是否撑得住 GA-2→GA-3？ | §8 |

### 0.2 一句话结论

> **可行。** 前提是：  
> 1）采用 **Hybrid RE**（规则托底 + 模型提案）；  
> 2）把「系统知识进化」（KE/Genome）与「模型权重进化」（LoRA）拆成双轨；  
> 3）自我数据蒸馏从 **Shadow 回路 B** 起步，不等待 LIVE；  
> 4）用明确的 **升级 / 熔断 / 回退** 条件管理 2B 的能力边界，而不是假设它「训完就懂事」。

**可行性评级（Proposed）：**

| 维度 | 评级 | 说明 |
|---|---|---|
| 契约与门禁合规 | **高** | Schema + Validator 可逼近 100% |
| 五骨架日常判断 | **中高** | SFT 后可支撑 Shadow 与低风险 LIVE |
| 模糊因果鉴别 | **中** | 依赖 KE 检索与 FE 质量；2B 有天花板 |
| 真·开放域自进化 | **中低（首年）** | 须靠双轨：知识进 KE，通用推理进权重 |
| 工程落地成本 | **可控** | 1–2 GPU + 小团队；不依赖真实写权限即可启动 |
| 与 GARP 研究主张匹配 | **高** | 补上 Workflow Agent 缺的「可改写认知部件」 |

## 1. 可行性判断框架

### 1.1 什么样的任务「适合专项微调小模型」

| 适合 | 不适合（应交给规则/门禁/人审） |
|---|---|
| 结构化摘要 → 结构化决策草稿 | 最终批准与执行 |
| 场景归类、假设表述、幅度建议 | hard_block、Trust 本体计算 |
| NO_ACTION / HOLD 的有依据选择 | 平台 API 语义与凭证 |
| 对齐目标函数的可读说明 | 精确数值最优化（竞价求解） |
| 从失败包中提炼「下次应避免什么」 | 无治理的经验全局硬编码 |

GARP 的 RE 岗位 **大部分落在左列**——这是「可行」的结构性原因。

### 1.2 可行性三支柱

```text
        ┌──────────────────┐
        │  契约可约束        │  ReasoningBundle 可 Schema 化
        └────────┬─────────┘
                 │
     ┌───────────┼───────────┐
     ▼           ▼           ▼
 数据可闭环    评估可证伪    失败可回退
 Shadow/RFE   分 env 指标    Validator/规则熔断
 提供蒸馏语料  投手基线对照    上一 LoRA / rules-only
```

缺任何一柱，2B 路线会从「工程可行」退化为「不可验证的黑盒」。

## 2. 技术可行性分项预判

### 2.1 容量可行性（2B 够不够）

| 子能力 | 2B 预期 | 加强手段 | 风险等级 |
|---|---|---|---|
| JSON / 枚举契约 | 训后可达标 | guided decode + V-01 | 低 |
| 五骨架路由 | 80–90% 可达 | 分层采样 + 特征模板 | 低 |
| 幅度落在 Risk 预览内 | 易达标 | 先验注入 + V-02 硬闸 | 低 |
| NO_ACTION 正确性 | 可训到业务可用 | 收割稳定子集加权 + RFE 反馈 | 中 |
| 多信号假设鉴别 | 弱于专家 | KE/RAG 摘要；否则 HOLD | **中高** |
| 长尾新场景 | 不可靠 | knowledge_basis=[] → HOLD/ESC | **高** |
| 置信度校准 | 差 | 仅展示，不作门禁 | 中 |

**预判：** 在 Hybrid 与五骨架封闭问题域内，2B **够支撑 GA-2 Shadow 与低 Trust 试运行**；开放长尾与高风险活动决策 **不够单独扛**，必须降级路径。

### 2.2 数据可行性

| 数据源 | 冷启动 | 持续 | 预判 |
|---|---|---|---|
| Fixture / Mock State+FE | 主力 | 补充 | **无授权即可启动** |
| 规则 RE 金标 | 主力底线 | 对照 | 可行 |
| 教师 7B 合成 | 扩多样性 | 长尾 | 可行（须过滤） |
| 专家手写轨迹 | 高质量瓶颈 | 难例仲裁 | **人力是关键路径** |
| Shadow 包 + SRA 结果 | 中期 | 主力 | 依赖 B-M5 |
| RFE Report / Failure | 中期 | 主力难例 | 依赖回路 B 跑通 |
| LIVE 真实账户 | 不可默认 | 可选 | **须单独授权** |

**预判：** 数据可行性 **高**——因为架构自带 Decision Packet / Causal / Reflection 蒸馏接口，这是相对通用 Agent 项目的最大结构优势。

### 2.3 训练与迭代可行性

| 环节 | 可行性 | 备注 |
|---|---|---|
| LoRA SFT / DPO | 高 | 单卡可完成 |
| 契约回归自动化 | 高 | 应先于模型存在 |
| 偏好 pair 自动挖掘 | 中高 | Validator 失败 + SRA REJECT 是现成信号 |
| 在线学习（每包热更新） | **低 / 不建议** | 与审计、稳定性冲突；改为周期版本 |
| 多任务同一权重 | 中 | 建议 RE 主任务为主，RFE/LE 用独立 adapter |

### 2.4 运行与治理可行性

| 项 | 预判 |
|---|---|
| 本地私有部署 | 可行（数据不出域） |
| 延迟（日内回路） | 3B P95 约数秒内可满足 Shadow；LIVE 视硬件 |
| 可审计 | 可行：prompt 指纹 + bundle + Validator 日志 + model_version |
| 可回退 | 必须具备：`model_version` 写入包；熔断到 rules-only |
| 可否宣称「已验证」 | **否**，直到 GA-3 与标定完成 |

## 3. 实践中必然出现的瓶颈（前瞻，不是事后总结）

### 3.1 预期瓶颈清单

| ID | 瓶颈 | 最早出现阶段 | 典型症状 | 预置对策 |
|---|---|---|---|---|
| BN-01 | **过度 NA（不敢动）** | SFT-1 / DPO 后 | 显著恶化仍 NO_ACTION | under_action 门槛；恶化子集加权 |
| BN-02 | **刷存在感（乱动）** | SFT 早期 | 噪声内微调 | 收割稳定加权；P5 偏好对 |
| BN-03 | **JSON 偶发崩坏** | 全程 | 解析失败率抖动 | 强制 NA 回退 + 熔断 N 次 |
| BN-04 | **假设模板化** | SFT 中期 | cause_claim 空话、rival 重复 | 难例多样性；知识检索；专家改写 |
| BN-05 | **数值不敏感** | 业务场景 | 把 3% 跌幅当 30% | FE 摘要里给分位/噪声结论，不给裸数堆 |
| BN-06 | **知识幻觉** | RAG 未上时 | 编造 basis | V 禁字段 + 空 basis 白名单；DPO 负例 |
| BN-07 | **场景边界糊** | 骨架重叠时 | 种草/活动混用 | 特异性优先规则；骨架冲突样本 |
| BN-08 | **REVISE 循环低效** | 联调 | 同错重提 | revise_feedback 结构化；N_revise=2 熔断 |
| BN-09 | **教师数据偏见** | 数据合成 | 全是「稳妥 NA」 | 规则金标并行；投手抽检 |
| BN-10 | **分 env 指标虚高** | Shadow 后 | FIXTURE 过拟合 | 评估强制分 env；LIVE 单独表 |
| BN-11 | **权重腐蚀通用能力** | 持续学习后 | 换店/换类目失效 | 增量小步 + 通用语料回放 |
| BN-12 | **把易变规则烧进权重** | 设计失误 | 活动价、日阈值过时 | 规则进 KE/prompt；权重只学「怎么推」 |

### 3.2 两个最危险的失败模式

**失败模式 A：模型学会了「永远安全」**  
- 表现：NA 率过高，SRA 几乎不 REJECT，但经营无改善。  
- 为何危险：看起来合规，实际杀死决策价值，研究上无法证明 Growth。  
- 预警指标：`under_action_rate > 15%` 且「投手基线动作率」显著高于模型。  

**失败模式 B：模型学会了「绕过语义门禁」**  
- 表现：字段合法但语义危险——例如用多笔小动作拼大调整、或 ALTERNATIVE 被误当 PRIMARY。  
- 为何危险：单字段 Validator 放行，系统级风险仍升高。  
- 预警指标：累计幅度违规、同对象短窗多次包、SRA 多轮 REVISE 耗尽。  
- 对策：包级聚合校验（不只字段级）；Adapter G 集合最终硬闸不变。

## 4. 模型侧「自进化」目标预判

### 4.1 进化什么 / 永不进化什么

| 应沉淀进权重（慢变量） | 应留在 KE / Prompt（快变量） | 永不进权重 |
|---|---|---|
| 如何读摘要、归类场景 | 具体 Rule/Strategy 文本 | 凭证、写权限语义 |
| 如何写可反驳假设 | Parameter Genome 数值 | `review_result` |
| 如何在噪声前选择 NA | 当日活动价、类目打法 | 审计日志原文 |
| 如何对齐 objective 说明 | Failure Pattern 全文（检索用） | LIVE 未授权样本 |
| 如何响应 REVISE 反馈 | Trust/Risk 阈值表 | 伪造的「已验证」标签 |

### 4.2 自进化成熟度阶梯（Maturity）

```text
M-B0  契约固化     输出合法、禁字段为零
M-B1  骨架可路由   五骨架日常路径可用
M-B2  反思可改写   经 RFE 反馈后，同类错误下降
M-B3  蒸馏可闭环   Shadow→难例→LoRA→指标回升，可重复
M-B4  知识可协同   KE 新 Experience 能改善模型决策（RAG+SFT）
M-B5  域可迁移     新类目/新店靠 KE+少量数据启动，而非重训
```

**预判：** GA-2 阶段目标应锁定在 **M-B3**（可重复的自蒸馏闭环）；M-B4/M-B5 属 GA-3 及以后。不要在未达 M-B3 时宣称「自进化已成立」。

### 4.3 各成熟度的可证伪目标（Proposed）

| 成熟度 | 可证伪目标 | 证据形态 |
|---|---|---|
| M-B0 | schema_valid ≥ 99%；禁字段 ≈ 0 | 回归报告 |
| M-B1 | skeleton_route_acc ≥ 85%；NA-P ≥ 0.90 | 锁定测试集 |
| M-B2 | 对 REVISE 难例再训后，同类 gate_violation ↓ ≥ 50% | 前后对比 |
| M-B3 | 完成 ≥ 2 轮「Shadow 挖掘→微调→同分布指标回升」 | 版本 lineage |
| M-B4 | 注入新 Experience 摘要后，对应场景 reasonableness ↑ | RAG 消融 |
| M-B5 | 新类目 ≤ N 条专家轨迹达 M-B1 | 迁移实验 |

### 4.4 自进化的触发器与节奏（预判）

| 触发器 | 阈值（Proposed） | 动作 |
|---|---|---|
| 定期 | 每 1–2 周 | 增量 SFT/DPO（数据过闸后） |
| schema 崩 | 连续 3 日 < 97% | 回滚 + 紧急契约重训 |
| NA 失真 | under/over 越门槛 | 定向难例重配比 |
| 新骨架/域注册 | 注册事件 | 必做增量，禁止静默上线 |
| SRA REJECT 率 | 相对基线 +50% | 冻结部署，规则-only 接管 |
| TCAL 阈值大改 | Prompt 约束摘要变更 | 同步微调评估，防分布漂移 |

**节奏预判：** 不要按「每包热更新」设计；应按 **周级版本列车** + 紧急回滚。自进化要「可审计地慢」，这是研究可信度的一部分。

## 5. 自我数据蒸馏目标预判

### 5.1 蒸馏飞轮（与回路 B 对齐）

```text
                    ┌─ 规则 RE / 教师 / 专家（冷启动）─┐
                    ▼                                   │
              Brain 产出 Bundle                         │
                    ▼                                   │
         Gate（RKE/TE/SRA）+（Shadow 不外发）            │
                    ▼                                   │
              Decision Packet ── outcome_ref ──┐        │
                    ▼                         │        │
              RFE Report / Finding ◄──────────┘        │
                    ▼                                   │
         ┌──────────┼──────────────┐                   │
         ▼          ▼              ▼                   │
      难例包      偏好 pair      经验候选              │
    （违规/误判） (优 vs 劣)   (LE→KE 治理)            │
         │          │              │                   │
         ▼          ▼              ▼                   │
      增量 SFT    DPO 重训     RAG/KE 检索增强 ◄───────┘
         └──────────┴──────────────┘
                    ▼
              新 model_version → 下一班 Shadow
```

**关键点：** 自我蒸馏的「原材料」不是模型自己瞎采，而是 **门禁结果 + 复盘结果**——这正是 Decision Packet 作为成长最小原子的价值。

### 5.2 蒸馏目标（按对象）

| 蒸馏对象 | 目标 | 质量门（Proposed） | 去向 |
|---|---|---|---|
| **契约样本** | 合法 Bundle 分布 | schema_valid=100% | SFT-0 回放 |
| **骨架样本** | 五骨架均衡覆盖 | 每骨架 ≥ 阈值 | SFT-1 |
| **偏好 pair** | 拉开合规/违规间隔 | 金标或高分 vs 失败包 | DPO |
| **失败模式集** | BN-01…BN-12 对抗 | 每模式 ≥ 100 有效 | 定向重训 |
| **假设改写对** | 空话 → 可反驳假设 | 专家或强教师改写 | SFT/偏好 |
| **NO_ACTION 对** | 正确不动 vs 误动/该动不动 | RFE 后验 | 加权 SFT/DPO |
| **知识摘要** | KE Experience → prompt 片段 | 治理通过、带 version | RAG，**不优先烧权重** |
| **负知识** | Failure Pattern 禁做清单 | 不可无痕删除 | prompt 负例 + DPO |

### 5.3 蒸馏产率与瓶颈（务实预期）

| 阶段 | 环境 | 可用蒸馏产率（粗估） | 主要损耗 |
|---|---|---|---|
| 冷启动 | Fixture + 规则 | 高（可控） | 多样性不足 |
| Shadow 早期 | SIM/SHADOW | 中 | 模型自身错误污染；须 Validator 滤 |
| Shadow 中期 | SHADOW + RFE | 中高 | 专家抽检人力 |
| LIVE（若授权） | LIVE | 低→中 | 延迟、噪声、合规审查 |

**预判：** 前 8–12 周 **不依赖 LIVE** 也能完成 M-B0–M-B2；M-B3 的第二轮闭环质量取决于 RFE 是否产出可判对错的 Finding，而不是取决于有没有真实写权限。

### 5.4 自我蒸馏的反模式（必须预判并禁止）

| 反模式 | 为何致命 | 硬闸 |
|---|---|---|
| 模型自产自评当金标 | 自我强化偏差 | 金标须规则/教师/专家至少一方 |
| 把 Shadow 成功当 LIVE 真值 | 伪标定 | `source_env` 分报告 |
| 无治理直接把包写进 SFT | 门禁被训练腐蚀 | 过闸流水线（§5.5） |
| 只留 APPROVE 丢 REJECT | 丢掉最有信息量的负例 | 失败必进难例集（P6） |
| 周期全量重训无 lineage | 不可审计回滚 | 数据快照 hash + 版本表 |
| 易变经营参数进 SFT 答案 | 权重过时即错 | 答案层只出动作语义，数值跟 Genome/预览 |

### 5.5 数据过闸流水线（Governance Gate）

```text
原始事件包
  → G1 来源合法（env 标签完整；无密钥/PII）
  → G2 契约完整（Packet 字段可重建 Prompt）
  → G3 结果可判（SRA 结果 或 outcome/RFE 至少其一）
  → G4 去重与泄漏检查（prompt 指纹）
  → G5 配比控制（骨架/失败/NA 均衡）
  → G6 人工抽检（比例 Proposed：高风险类 5–10%，其余 1–3%）
  → 入训练集 / 偏好集 / 仅评估集
```

**不过 G1–G3 的数据不得进入权重训练**（可进评估观察）。

## 6. 分阶段可行性结论

| 阶段 | 目标 | 可行性 | 成功判据（Proposed） | 若失败 |
|---|---|---|---|---|
| F0 计划与夹具 | 契约+Fixture+Validator | **高** | 回归绿；五骨架夹具齐 | 不进模型 |
| F1 契约模型 | SFT-0 | **高** | Exit-A | 修数据/模板，不硬训 |
| F2 业务模型 | SFT-1 | **中高** | Exit-B；投手对照可接受 | 加 RAG / 专家 / 考虑 4B |
| F3 对齐模型 | DPO | **中高** | Exit-C；防 BN-01/02 | 调偏好配比 |
| F4 Shadow 联调 | Hybrid RE 上线无写 | **高（工程）** | Exit-D；双轨 A/B 有报告 | 规则-only 兜底 |
| F5 蒸馏闭环 | 第 1 轮难例→微调→回升 | **中** | 错误率可重复下降 | 强化 RFE Finding 质量 |
| F6 低风险 LIVE | Trust 低、幅度小 | **有条件** | SRA APPROVE 率与后验达成不劣于规则 | 收回写半径 |
| F7 高自治 | Trust 升、大动作 | **本报告不预判为可行** | 须 GA-3 | 保持人审/规则 |

### 6.1 总可行性公式（工程表述）

```text
可行(Hybrid Brain)
  = 契约可约束
  ∧ 门禁不可绕
  ∧ Shadow 数据可回流
  ∧ RFE 能给出可学习信号
  ∧ 版本可回滚
  ∧ 指标分 env 可证伪
```

当前 GA-2 文档集对右端 **全部有接口级支撑**——这是本报告给出「可行」的核心依据，而不是对 2B 智力的乐观假设。

## 7. 升级 / 熔断 / 回退决策树

```text
Shadow 评估
  │
  ├─ schema/gate 违规高 ──────────► 回退 rules-only + 紧急契约重训
  │
  ├─ over_action 高（BN-02）──────► DPO 加「噪声内 NA」对；收紧幅度先验
  │
  ├─ under_action 高（BN-01）────► 恶化子集加权；投手对照；必要时 4B
  │
  ├─ 假设质量差（BN-04）─────────► 上 RAG(KE)；专家改写对；暂缓 LIVE
  │
  ├─ 长尾崩溃（M-B5 不达标）────► 保持 HOLD/ESC；不扩域
  │
  └─ 全指标达标 ────────────────► 进入低风险 LIVE 试运行（须新授权）
```

**升级到 4B/7B 的触发（Proposed）：**  
Exit-B 连续两轮不达标，且已用尽 RAG + 专家对 + 配比调整，仍 `under/over` 或 reasonableness 低于投手基线的 70%。

**永久保留 rules-only 通道的原因：**  
模型版本回滚、证书故障、分布剧变时的业务连续性；也是研究上的 **对照臂**，不是失败象征。
